# Multipage Image Workflow

## Overview

A system for building multi-page websites where Claude handles all code and links,
and clients manage only image content through a backoffice CMS backed by fal.ai generation.

---

## Core Principle

**Claude's domain:** All frontend code, all links (static + dynamic), all image slot definitions, all prompts.  
**Client's domain:** Images only — review prompts, generate, approve, publish.

---

## Build Order

### Phase 1 — Schema & Backoffice First
Build the backoffice before any frontend. It is the content engine everything else depends on.

1. Supabase schema (projects, pages, image slots, assets)
2. Backoffice shell — auth, navigation, project setup
3. Global assets section
4. Page management section
5. Image generation pipeline (fal.ai integration)
6. Publish controls

### Phase 2 — Frontend Build
Only begins after backoffice is operational and image workflow is confirmed.

1. Receive full app UI (all pages shown upfront)
2. Cross-page analysis — deduplicate shared images across all pages in one pass
3. Build all pages with grey placeholder blocks
4. All links (static + dynamic) coded correctly — client touches nothing here
5. Frontend pulls images from Supabase storage by slot key

---

## Adding a New Page (Ongoing Flow)

```
User wants new page
       ↓
Upload UI mockup OR generate UI mockup via built-in AI tool
       ↓
Claude analyzes design
       ↓
Image slots created with scope classification + pre-filled prompts
       ↓
User reviews prompts → generates images (queued, not bulk)
       ↓
Images approved → Claude builds the page
       ↓
Page published
```

---

## Image Scope Layers

Every image slot is classified into one of three scopes at analysis time.

| Scope | Description | Example | Generated |
|---|---|---|---|
| Global | Used across multiple pages | Logo, brand hero, team photos | Once, referenced everywhere |
| Component | Tied to a reusable component | Navbar bg, footer image, card style | Once per component type |
| Page | Unique to a single page | About page timeline image | Per page |

**Key rule:** When the full app UI is provided upfront, Claude identifies all cross-page duplicates before any slots are created. Same image on 8 pages = 1 slot, 8 references.

## Supabase Schema

```sql
-- Projects
projects (
  id, name, brand_style_prompt, created_at
)

-- Pages
pages (
  id, project_id, name, slug, status, created_at
)

-- Image Slots
image_slots (
  id,
  project_id,
  page_id,           -- null if global or component scope
  component_type,    -- null if not component scope
  scope,             -- global | component | page
  key,               -- semantic name e.g. "brand-logo", "hero-bg"
  prompt,            -- pre-generated by Claude
  alt,               -- pre-generated by Claude
  dimensions,        -- { width, height, aspectRatio }
  asset_id,          -- FK to assets once generated
  status             -- pending | generating | generated | approved
)

-- Assets (generated or uploaded images)
assets (
  id,
  project_id,
  storage_url,       -- Supabase storage
  prompt_used,
  generated_at,
  source             -- fal_ai | upload
)
```

## Batch Generation — Controlled Queue

**Do not bulk generate all at once.**

### Why
- fal.ai rate limits throttle large concurrent requests
- Cost spikes with no review gate
- Partial batch failures create inconsistent state
- Bad prompt → bad image → already spent, no review

### How
- Queue-based: process 4-5 images at a time
- Each result shown immediately for review
- User can pause queue, edit a prompt, regenerate a single slot
- Failed slots retry automatically with exponential backoff (2s, 4s, 8s)
- Running cost displayed live so client controls spend

### Generation Order
Always generate in scope order — most reuse value first:
1. Global assets (used everywhere, highest leverage)
2. Component images (shared across multiple pages)
3. Page-specific images (unique, generated last)

## Brand Style Prompt

A single brand style descriptor stored at project level, prepended to every fal.ai prompt.

```
"Clean, minimal, professional photography style. 
 Warm neutral tones. Modern B2B aesthetic."
```

Ensures all generated images feel visually cohesive across the entire site.
Client sets this once in project settings. Affects all generations.

## Backoffice Structure

```
Project Settings
  └── Brand style prompt
  └── fal.ai model selection (FLUX, SDXL etc.)

Global Assets
  └── All scope:global slots
  └── Generate first before touching pages

Components
  └── Navbar, Footer, Card styles etc.

Pages
  └── Page list with status indicators
  └── Per page: slot list, prompts, generate controls
  └── Add New Page → UI upload/generate flow

Publish
  └── Per-page publish (blocked if any slots still pending)
  └── Global publish all approved pages
```

## New Page UI Generation Flow

When a client wants to add a page without an existing design:

1. Backoffice offers two options:
   - **Upload** — drop a Figma export, screenshot, or mockup
   - **Generate** — describe the page, AI generates a UI mockup
2. Claude analyzes the design
3. Slots auto-created with scope, dimensions, prompt, alt
4. Any images already in Global/Components are linked — not duplicated
5. Only net-new slots are created for this page
6. Client reviews and generates

---

## Frontend Integration

- Each image slot rendered as a grey block during development
- Block carries its `slot key` as a data attribute
- At runtime, component fetches image URL from Supabase by slot key
- If no approved image yet → grey placeholder remains
- When image is approved in backoffice → frontend reflects it immediately (no redeploy)

## What Claude Handles vs Client

| Responsibility | Claude | Client |
|---|---|---|
| Frontend code | Yes | No |
| Static links | Yes | No |
| Dynamic links (auth, routes, params) | Yes | No |
| Image slot definitions | Yes | No |
| Prompt generation | Yes (can edit) | Review only |
| Image generation | No | Yes (via backoffice) |
| Image approval | No | Yes |
| Brand style prompt | Suggests | Sets |
| New page UI design | Assists | Initiates |
